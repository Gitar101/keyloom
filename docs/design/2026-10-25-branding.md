# Keyloom branding and launch assets

## Approved direction

A pixel-art monitor and keyboard share cyan, violet, and amber regions. The
mark must remain readable at 16 pixels, with no lettering or soft gradients.
The same mark supplies the favicon, Windows executable, desktop shortcut,
and native window icons. Existing lighting behavior and device commands stay
unchanged.

The blog cover combines the user-supplied keyboard photograph, the actual
Keyloom UI screenshot, and the new mark through an image-editing workflow.
Keep the UI flat and readable. Preserve the keyboard's compact layout. Use
original Keyloom copy rather than the manufacturer's advertisement headline.
Label the cover as edited artwork, not a new photograph of verified output.

The X post and first-person blog explain spatial mapping, independent fades,
black-to-off behavior, and local capture. Do not claim universal compatibility,
guaranteed frame rates, proven flicker elimination, or guaranteed virality.
Use a small set of relevant hashtags and link to the public project.

## Implementation checklist

1. Generate reproducible SVG, pixel PNG, and multi-resolution ICO assets.
2. Apply the icon to Tk windows and package the same assets with PyInstaller.
3. Produce and inspect one multi-reference image edit; preserve exact UI pixels
   with a local composite if the edit changes the screenshot.
4. Write the X post, blog, artwork credits, and v0.1.1 release notes.
5. Run unit tests, check packaged icons, and run a preview-only smoke test.
6. Audit the explicit public file list and executable for private material.
7. Commit and publish v0.1.1 with the executable and SHA-256 checksum.

## Boundaries and acceptance

- No hardware writes are needed for branding verification.
- Do not publish original uploads, local diagnostics, private notes, logs,
  memory, recordings, or local absolute paths.
- Only the icon assets are added to the executable, not blog images.
- Source code and the new icon remain MIT licensed. The supplied keyboard
  photo and manufacturer marks retain their respective owners' rights.
- Tests must cover icon dimensions, transparent pixel-art palettes, ICO
  variants, and native-window icon application. The packaged smoke test must
  load its bundled icons and complete without error in preview-only mode.

The user approved this direction and the v0.1.1 publication on 2026-10-25,
then explicitly requested that the image edit include both uploaded images.
